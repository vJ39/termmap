気象警報・注意報(濃霧注意報等)をルート沿いに表示する機能(#79)のための、データソース調査結果
(2026/08/16、実APIアクセスで確認済み)。

## 結論

気象庁の防災情報JSON(既存の`src/radar.rs`が使っている`jma.go.jp/bosai/`と同系統)で、
警報・注意報の状態は無料・認証不要で取得できることを確認した。ただし取得できるのは
**市区町村より広いエリア単位のコード**であり、地図上の座標(緯度経度)には直接対応しない。
「ルート沿いに表示する」には、エリアコード→表示位置のマッピング方法を別途設計する必要がある。
実装は可能と判断するが、設計フェーズで座標マッピング方式を詰めてから着手する。

## データソース

| 項目 | 値 |
|---|---|
| エンドポイント | `https://www.jma.go.jp/bosai/warning/data/warning/{都道府県コード6桁}.json`(例: 東京都=`130000`) |
| 認証 | 不要・無料 |
| 更新頻度 | 気象庁が警報・注意報を発表/解除するたびに更新(既存radar.rsのナウキャストと違い定期更新ではなく随時) |
| レスポンス形式 | JSON。`areaTypes[].areas[]`に、エリアコード(`code`)ごとの`warnings[]`(警報種別コード`code`+状態`status`: 発表/継続/解除/発表警報・注意報はなし) |

### 実際に確認したレスポンス例(東京都、2026/05/28時点のキャッシュ)

```json
{
  "reportDatetime": "2026-05-28T10:16:00+09:00",
  "publishingOffice": "気象庁",
  "headlineText": "伊豆諸島南部では、強風や高波に注意してください。...",
  "areaTypes": [{
    "areas": [
      { "code": "130010", "warnings": [{ "status": "発表警報・注意報はなし" }] },
      { "code": "130020", "warnings": [{ "code": "14", "status": "継続" }, { "code": "20", "status": "継続" }] },
      { "code": "130040", "warnings": [{ "code": "20", "status": "解除" }] }
    ]
  }]
}
```

### 警報種別コード(一部、Web検索で確認)

| コード | 意味 |
|---|---|
| `20` | 濃霧注意報 |
| `14` | (要確認。大雨警報系と推測されるが今回未確定) |

正確な対応表は気象庁の公式コード表(`https://www.jma.go.jp/bosai/common/const/warning.json`相当、または
`https://www.data.jma.go.jp/developer/`の資料)を実装時に取得して確定させる必要がある。

## 課題: エリアコード→座標のマッピング

`https://www.jma.go.jp/bosai/common/const/area.json`を確認したところ、`class10s`/`class15s`/`class20s`
(気象庁の地域区分、市区町村相当を含む)の定義はあるが、**座標情報(緯度経度・ポリゴン境界)は
含まれていない**(`name`/`enName`/`kana`/`parent`のみ)。

つまり、warning.jsonが返す`code`(例: `130020`)を地図上に描くには、以下のいずれかが必要:

1. 気象庁のエリア境界ポリゴン(GeoJSON)を別途入手する(気象庁が公式に提供しているか要確認。
   国土数値情報や外部の非公式変換データが存在する可能性がある)。
2. エリアごとの代表点(例えば地域の中心都市の座標)を自前で用意する(精度は粗いが実装コストは低い)。
3. ルート沿いの各通過点について、その地点が属する警報エリアコードを逆引きする方法が必要になる
   (方法1のポリゴンが無いと、逆引き自体ができない)。

「ルート沿いに表示する」という要件からは、方法1(ポリゴン)が本来望ましいが、データ入手性が
未確認のため、設計フェーズで代替案(方法2の簡易実装等)も含めて検討する。
