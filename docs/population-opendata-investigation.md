(2026/08/16、Web検索ベース)。

## 結論

国土数値情報(国土交通省)の「500mメッシュ別将来推計人口データ」が無償・登録不要で利用できる。
ただし既存のtermmapのデータソース(JARTIC/Overpass/NIED、いずれもbboxクエリでその場取得する
API形式)とは提供形態が異なり、**都道府県単位の静的ファイルダウンロード**(GeoJSON/Shape形式)
である点が実装方式に影響する。

## データソース

| 項目 | 値 |
|---|---|
| 提供元 | 国土数値情報(国土交通省) `https://nlftp.mlit.go.jp/ksj/` |
| データ名 | 500mメッシュ別将来推計人口データ(最新版R6国政局推計) |
| 認証 | 不要 |
| 料金 | 無償(地理空間情報活用推進基本法等に基づく提供) |
| 提供形式 | 都道府県単位のファイルダウンロード。GML(JPGIS2.1)/Shape/GeoJSON |
| 更新頻度 | 数年に1回(国勢調査・推計人口の改定タイミング) |

## 既存データソースとの違い(実装方式への影響)

既存の4種(交通量/主要道路/カメラ/通行規制)+過去災害データ(#75)はいずれも、現在の画面bboxを
その都度APIへ問い合わせて取得する方式(#84の`PlotLayer`フレームワーク)。人口メッシュデータは
これと異なり、**都道府県単位の静的ファイルを事前にダウンロードしてローカルに持つ**方式になる。

実装方式の選択肢:

1. **アプリ内蔵**: 全国分をビルド時に埋め込む。500mメッシュは全国で数十万件規模になり得るため、
   サイズ・更新性(数年に1回の改定にビルドし直しが必要)の観点で要検討。
2. **初回起動時ダウンロード+ローカルキャッシュ**: 表示している都道府県のファイルを初回アクセス時に
   ダウンロードし、`#84`のディスクキャッシュ層(`plotcache.rs`)とは別の恒久キャッシュとして持つ
   (人口メッシュは頻繁に変わらないため、TTLでの期限切れは不要かfreshに近い扱いでよい)。
3. **見送り**: 実装コストに対して、地図アプリ(ツーリング用途)での人口動態表示の必要性を再検討する。

## 次のステップ

「人口動態」単体としては選択肢2が妥当と考えられるが、都道府県単位ファイルのサイズ・
パース処理のコストは未検証(実際に1都道府県分をダウンロードして確認する追加調査が必要)。
タスク後半の「視認性重視の設定項目を増やす」は、人口動態表示とは独立した課題
(#75/#71-74等、地図上の情報密度が増えたことに対する透明度・表示密度・フィルタ設定の
拡充)である可能性が高く、別途スコープを分けて検討する。
